## はてなブログをやめて、個人サイトに移った
いままで個人ブログとしては、はてなブログの有料プランをつかってきたのですが、最近は技術系の記事はzennに書くことあり、記事の二重管理が続いていました。
また、有料プランのメリットも薄れてきたので、個人サイトに移行することに決めました。

とはいえ、個人サイトを作成したところで、zennとの二重管理は続きます。
そこで、zennと個人サイトに同時に記事を配信する仕組みを作ることにしました。

そこでできたのが、[koylog.com](https://koylog.com/) です。
zennに投稿した記事 + 雑記などの個人記事を一つの場所に同居させています。

## どうやるか？
zennにはすでに、githubを使って記事を管理する仕組みがあります。
その仕組にのっとり、記事の管理をgithubに一本化し、zennと個人サイトの両方に配信することにしました。


```
              ┌→ zenn.dev     (articles/ のみ)
1つのリポジトリ ─┤
              └→ koylog.com   (articles/ + posts/)
```

- `articles/` … Zennにも出す技術記事
- `posts/` … 自サイトだけに出す記事（はてなから移したもの等）

フロントエンドは、[Astro](https://astro.build/) をつかって作成し、ホスティングは、[Cloudflare Workers](https://workers.cloudflare.com/) をつかっています。
独自ドメインもCloudflareで取得してます。

## 実装

### Zennと個人記事を同居させる

同居といっても、特別なことはしていません。
Zennが見にいくのは `articles/` だけなので、その隣に `posts/` を置けば、後者は自動的に自サイト限定の記事になります。Zenn側には何も設定を足していません。

自サイト（Astro）側では、この2つのディレクトリをそれぞれ別のコレクションとして読み込み、技術記事と雑記として扱いを分けています。

そのうえで、記事のfrontmatterはZennのものをそのまま流用しています。
`title` / `emoji` / `type` / `topics` / `published` はZennが元々要求している項目なので、自サイトのために項目を足したり詰め替えたりする変換レイヤーが要りませんでした。下書きが自サイトにだけ漏れて公開されないのも、Zennと同じ `published` を見ているだけです。

結果として、書くときの手順は今までと変わりません。`zenn new:article` で記事を作って `git push` すれば、両方が更新されます。

### Zenn記法をそのまま使う

同居させるうえで一番の問題が記法でした。
Zennには `:::message` のような独自記法があり、普通のMarkdownパーサに通すと当然崩れます。

ここは、Zenn自身が記事の表示に使っているパッケージをそのまま借りました。Zenn記法込みでHTMLに変換してくれる `zenn-markdown-html` と、その見た目を再現する `zenn-content-css` が公開されています。自サイトは記事の本文をそこに通して表示しているだけです。

おかげでメッセージもアコーディオンも各種埋め込みも、Zennとほぼ同じ見た目になります。
Markdownの拡張を自前で書かずに済んだのは大きくて、いまも記法の互換性を気にせず記事を書けています。

### その他

- 画像はリポジトリの `images/` を原本にして、ビルド前に自サイト側へコピーするだけ
- ホスティングは Cloudflare Workers。静的アセットは無料・無制限
- ランニングコストはドメイン代だけ（年約1,900円）


## 結果

- `git push` 一発で、Zennと自分のサイトの両方が更新される
- 書くときの手順は今までと変わらない（`zenn new:article` のまま）
- 記事も画像もGitの履歴に入り、はてなとZennのどちらが終わっても手元に残る
- この記事も、その仕組みで両方に配信されている
